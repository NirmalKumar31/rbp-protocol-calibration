# Versions for the OFFLINE VERIFICATION environment, which is the scope and was not stated.
#
# This pins what `scripts/verify.py --local results/tables` and the test suite need. It
# deliberately does NOT pin torch, transformers, multimolecule or peft: those are needed to
# reproduce the GPU sweeps, not to check the released numbers, and pinning them here would
# force a large install on a reader who only wants to verify. docker/requirements-gpu.txt
# is the environment for reproduction.
#
# WHY THIS EXISTS. README tells a reader to `pip install -e .`, and pyproject declares lower
# bounds only -- numpy>=1.26 and so on -- so that command is free to resolve a numpy released
# next year. docker/requirements-cpu.txt has been pinned all along, but the container is not
# what a reader verifying the paper runs.
#
#   pip install -e . -c constraints.txt
#
# Not a full lock file. It pins what the results depend on numerically and leaves transitive
# packaging dependencies to resolve, which is the trade a lock file makes in the other
# direction: a full lock would be reproducible and would break on any platform whose wheels
# differ, and this repository is verified on macOS, on Linux CI and in two containers.
#
# Regenerate with:  pip freeze | grep -iE '^(numpy|pandas|scipy|scikit-learn|pyyaml|torch|transformers|matplotlib)='
